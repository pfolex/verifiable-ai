# AIX Evaluation Harness Audit & Gap Matrix (`EVAL-01` / Issue #40)

## 1. Executive Summary

This document audits the already-merged `EVAL-001` through `EVAL-007` evaluation harness modules in `verifiable-ai` and maps what is directly reusable for `AIX-Zero` versus what requires targeted extensions across `EVAL-02` through `EVAL-16`.

To prevent parallel incompatible evaluation codepaths, [`aix_zero/eval_harness_bridge.py`](../aix_zero/eval_harness_bridge.py) adapts `AIX-Zero` checkpoints and baseline reports directly into the canonical `EVAL-001` (`evaluation-result-v1.schema.json`), `EVAL-002` (`Provider` / `ProviderResponse`), `EVAL-003` (`benchmark_runner.py`), and `EVAL-006` (`statistical_gate.py` `paired_interval`) contracts.

## 2. Audit of Merged `EVAL-001` through `EVAL-007` Modules

| Existing Task | Module & Schema | Current Capabilities | Direct Reuse for AIX-Zero | Current Limitations / Hardcoded Assumptions |
| :--- | :--- | :--- | :--- | :--- |
| **`EVAL-001`** | [`evaluation_result.py`](../evaluation_result.py), [`schemas/evaluation-result-v1.schema.json`](../schemas/evaluation-result-v1.schema.json), [`schemas/evaluation-result-v1.1.schema.json`](../schemas/evaluation-result-v1.1.schema.json) | Validates `run_id`, `created_at`, `dataset` (`name`, `revision`, `split`, optional `manifest_sha256`), `model` (`provider`, `model_id`, `revision`, `parameters`, `adapter_version`), `scorer`, per-sample `score` in `[0, 1]`, `latency_ms`, token counters, and finite `mean_score`. | **100% Reusable.** `AIX-Zero` neural-only and symbolic-assisted runs validate cleanly against `evaluation-result-v1.schema.json` with zero schema changes. | `model.parameters` is untyped JSON; separation of `neural_only` vs. `symbolic_assisted` (`inflight_alu`) must be enforced by adapter conventions (`EVAL-02`). |
| **`EVAL-002`** | [`provider_adapters.py`](../provider_adapters.py) | Defines `ProviderResponse` (`output`, `input_tokens`, `output_tokens`, `cached_input_tokens`, `cost_usd`, `error`) and `Provider` protocol (`model`, `generate(sample_id, task)`), plus `ReferenceProvider` and `ReplayProvider`. | **100% Reusable.** Extended by `AIXZeroProvider` in [`aix_zero/eval_harness_bridge.py`](../aix_zero/eval_harness_bridge.py) so `AIX-Zero` runs as a standard local `Provider` with measured token counts and explicit `assistance_mode`. | Does not natively carry latent `ponder_depth` or `verifier_confidence` in `ProviderResponse` (tracked for `EVAL-09`). |
| **`EVAL-003`** | [`benchmark_runner.py`](../benchmark_runner.py) | Runs any `Provider` over `cases` (`[{"sample_id", "input"}]`), enforces unique sample IDs, records wall-clock `latency_ms`, isolates provider/scorer exceptions as zero-score error samples, and atomically writes validated results. | **100% Reusable** when `manifest=None` (computes canonical `manifest_sha256` over `cases`) or with VeriSci manifests. | When `manifest` is passed, `run_benchmark()` calls `dataset_manifest.validate_manifest(manifest)`, which is currently locked to VeriSci's 4 domains (`logic`, `silicon`, `systems`, `matter`). |
| **`EVAL-004`** | [`dataset_manifest.py`](../dataset_manifest.py), [`schemas/dataset-manifest-v1.schema.json`](../schemas/dataset-manifest-v1.schema.json) | Canonical SHA-256 manifest digesting (`manifest_digest`), duplicate sample ID rejection, public-field projection (`public_task`), and deterministic seed/domain ordering checks. | `manifest_digest` and canonical JSON hashing are **reusable**. | Schema hardcodes `dataset.name == "rlvr-forge-procedural"`, `scorer.name == "verisci-reward"`, and `domains` enum `["logic", "silicon", "systems", "matter"]`. Generalizing to AIX 21+ domains and template-family split manifests is scoped to `EVAL-03`. |
| **`EVAL-005`** | [`comparison_report.py`](../comparison_report.py), [`schemas/comparison-report-v1.schema.json`](../schemas/comparison-report-v1.schema.json) | Computes paired per-sample deltas (`candidate_score - baseline_score`), win/tie/loss counts, latency summaries (`mean`, `median`, `p95`), token/cost subtotals, and Markdown tables. | Paired delta, win/tie/loss, and Markdown table logic are **reusable**. [`aix_zero/eval_harness_bridge.py`](../aix_zero/eval_harness_bridge.py) provides `compare_aix_evaluation_results()` using the same schema structure. | `compare_results()` calls `validate_manifest()`, inheriting the 4-domain VeriSci enum until `dataset-manifest` is generalized in `EVAL-03`. |
| **`EVAL-006`** | [`statistical_gate.py`](../statistical_gate.py), [`schemas/regression-policy-v1.schema.json`](../schemas/regression-policy-v1.schema.json) | Implements `paired_interval()` (simultaneous Hoeffding confidence intervals with union bound across overall + per-domain constraints) and `assess_comparison()` (`PASS` / `FAIL` / `INCONCLUSIVE`), explicitly checking `independent_samples` and `min_samples_per_domain`. | `paired_interval()` and `validate_policy()` are **100% Reusable** for independent fixed-horizon evaluation sets. | Fixed-horizon Hoeffding bounds are conservative for small `N` (e.g., `N=5` per domain in v11 baseline gives `INCONCLUSIVE`, which is scientifically accurate) and do not support sequential stopping (`SPRT`) or cluster-robust template-group dependence (`EVAL-07`). |
| **`EVAL-007`** | [`ollama_provider.py`](../ollama_provider.py), [`run_ollama_Format_benchmark.py`](../run_ollama_Format_benchmark.py) | Live local HTTP adapter for Ollama models with digest pinning (`/api/tags`), strict URL validation, and public-only task boundary (`public_task`). | **100% Reusable** for comparing `AIX-Zero` against local Ollama baselines (`aix-8b:latest`, `aix3:latest`, etc.) on shared tasks. | Prompt instructions (`SUBMISSION_INSTRUCTIONS`) are specific to the 4 VeriSci JSON formats; multi-domain AIX comparisons require domain-neutral prompt templates (`EVAL-02`). |

## 3. Gap Matrix Mapped to `EVAL-02` through `EVAL-16`

| Roadmap Issue | Title | Gap Identified in `EVAL-001`–`EVAL-007` | Required Extension |
| :--- | :--- | :--- | :--- |
| **`EVAL-02 (#41)`** | Separate neural-only, arithmetic-repaired, solver-assisted, retrieved, and teacher-assisted modes | `evaluation-result-v1` allows arbitrary `model.parameters` without enforcing mode-separation tags or preventing cross-mode leaderboard mixing. | Enforce explicit `execution_mode` (`neural_only`, `symbolic_assisted`, `exact_solver`, `retrieved`, `teacher_assisted`) in `AIXZeroProvider` and reject mixed-mode claims. |
| **`EVAL-03 (#42)`** | Build leakage-resistant splits across template families, paraphrases, and novel compositions | `dataset-manifest-v1.schema.json` only represents flat `rlvr-forge-procedural` seeds over 4 domains and does not track template-family IDs, operand tuples, or paraphrase groups. | Add schema support for `template_family`, `composition_depth`, and disjoint train/val/test group hashes so template leakage fails validation. |
| **`EVAL-04 (#43)`** | Add baseline controls (majority, prior-only, random-route, shared-only, dense) | `EVAL-002` only includes `ReferenceProvider` and `ReplayProvider`. | Add deterministic control providers (`MajorityBaselineProvider`, `PriorOnlyProvider`, `SharedExpertOnlyProvider`, `RandomRouteProvider`) under `provider_adapters` / `aix_zero`. |
| **`EVAL-05 (#44)`** | Build an algebraic and arithmetic verifier suite | `verisci` covers propositional logic, boolean circuits, Lamport clocks, and molecular graphs, whereas `AIX-Zero` uses inline regex/arithmetic checks in `train_v4_from_scratch.py` and `bayesian_tasks.py`. | Unify exact rational/integer arithmetic, symbolic algebra, and intermediate step verification into a deterministic verifier module with negative/adversarial tests. |
| **`EVAL-06 (#45)`** | Build a sandboxed code and formal-check verifier | No subprocess-isolated code execution verifier exists in `EVAL-001`–`EVAL-007`. | Add resource-bounded, network-disabled subprocess verification for code-trace and formal assertions. |
| **`EVAL-07 (#46)`** | Implement sequential and fixed-horizon promotion gates (`SPRT` + grouped confidence intervals) | `statistical_gate.py` only implements fixed-horizon Hoeffding union bounds (`paired-hoeffding-union-bound`) and [`bayesian_tasks.py`](../aix_zero/bayesian_tasks.py) uses an empirical screen (`preregistered_empirical_screen_not_SPRT`). | Implement group-clustered confidence intervals (treating correlated layouts/templates as one cluster) and sequential probability ratio testing (`SPRT`) with explicit alpha/beta spending. |
| **`EVAL-08 (#47)`** | Measure retention and backward transfer across all previously supported domains | `fallback_audit` in [`train_bayesian_pilot.py`](../aix_zero/train_bayesian_pilot.py) checks trace preservation on v11's 21 domains but is not integrated into `statistical_gate.py`. | Formalize backward-transfer & non-regression gates across all prior domain manifests before any specialist or base checkpoint promotion. |
| **`EVAL-09 (#48)`** | Evaluate verifier calibration, abstention, and false-positive acceptance | `ValueVerificationHead` outputs `verifier_confidence` in `[0, 1]`, but `EVAL-001` samples do not record confidence or compute ECE / Brier / selective accuracy-coverage curves. | Extend evaluation summaries with Expected Calibration Error (ECE), Brier score, and false-positive acceptance rates on corrupted reasoning traces. |
| **`EVAL-10 (#192)`** | Build a Bayesian and probabilistic reasoning benchmark | [`aix_zero/bayesian_tasks.py`](../aix_zero/bayesian_tasks.py) implements binary `BP` and `BS` tasks; not yet packaged as a versioned `EVAL` manifest with multi-hypothesis and base-rate-neglect traps. | Package held-out exact rational Bayesian benchmarks under the unified manifest and verifier contract. |
| **`EVAL-11 (#193)`** | Build a causal intervention vs observation benchmark | `v12` prototype tested `CAUSAL_DO` arithmetic templates, but no interventional vs. observational (`P(Y|do(X))` vs `P(Y|X)`) structural causal graph verifier is in `main`. | Add formal SCM/backdoor-adjustment benchmark tasks with confounding controls. |
| **`EVAL-12 (#194)`** | Build a game-theoretic and mechanism-design benchmark | `v12` prototype tested 2x2 dominance arithmetic, but general Nash equilibrium, Pareto optimality, and incentive-compatibility verifiers are not in `main`. | Add exact normal-form and mechanism verification tasks. |
| **`EVAL-13 (#195)`** | Build an abstraction and compositional generalization benchmark | Existing v11 cases test held-out operand combinations within known templates (`same-template held-out arithmetic`). | Add compositional holds where primitive operators are trained separately and tested in unseen combinations (`length`, `depth`, and `operator-pair` holds). |
| **`EVAL-14 (#196)`** | Build an optimization, scheduling, and resource-allocation benchmark | `verisci` `systems` tests Lamport lock traces, not constrained objective optimization or feasibility margins. | Add exact constraint-satisfaction and resource-scheduling verifiers with optimality certificates. |
| **`EVAL-15 (#197)`** | Build a scientific law parsimony and counterfactual benchmark | Current physics/thermo domains in v11 provide formula parameters directly in the prompt. | Add hypothesis-selection and counterfactual perturbation tasks over noisy or multi-experiment observations. |
| **`EVAL-16 (#198)`** | Establish contamination, memorization, and canary auditing | `manifest_digest` hashes public cases, but there is no canary string injection or n-gram/template overlap scanner against training corpora. | Add automated train-test overlap auditing and canary-token leakage detection prior to benchmark signoff. |

## 4. Verification of Bridge Implementation (`EVAL-01`)

The bridge module [`aix_zero/eval_harness_bridge.py`](../aix_zero/eval_harness_bridge.py) and test suite [`aix_zero_tests/test_eval_harness_bridge.py`](../aix_zero_tests/test_eval_harness_bridge.py) verify that:
1. Committed `research/baseline/v11-local.json` (`neural_only` `9/105` and `symbolic_assisted` `105/105`) converts cleanly into validated `EVAL-001` (`evaluation-result-v1.schema.json`) artifacts via `baseline_report_to_eval_results()`.
2. `AIXZeroProvider` executes `AIX-Zero` through `benchmark_runner.run_benchmark()` (`EVAL-003`) while recording token counts, checkpoint SHA-256 revision, tokenizer SHA-256, and explicit `execution_mode` (`neural_only` vs `symbolic_assisted`).
3. Paired comparison and `statistical_gate.paired_interval()` (`EVAL-006`) run over `AIX-Zero` `neural_only` vs `symbolic_assisted` results and accurately flag small per-domain sample counts (`N=5`) as `INCONCLUSIVE` under fixed-horizon simultaneous Hoeffding bounds rather than overclaiming significance.
